# Як контриб'ютити

**[English version](./CONTRIBUTING.en.md)**

Дякуємо за інтерес — мета цього репозиторію рівно в тому, щоб спільними
зусиллями тримати холодний старт для нового розробника (Mac чи Windows)
максимально швидким і безболісним. PR, issue, пропозиції щодо нових
скриптів — welcome.

## Перш ніж відкривати PR

1. **Один PR — одна логічна зміна.** Новий скрипт, багфікс в існуючому,
   правка документації — окремі PR, не змішувати.
2. Якщо додаєте **новий скрипт** — спочатку відкрийте issue з коротким
   описом, що він робить і навіщо: нумерація в цьому репозиторії наскрізна
   і закріплена назавжди (див. нижче), номер видається при прийнятті ідеї,
   не заднім числом після того, як PR вже написаний під довільним ім'ям.
3. Якщо правите існуючий скрипт — **не перейменовуйте файл і не міняйте
   його номер**, навіть якщо логіка сильно змінюється. Номер = ім'я файлу,
   закріплений один раз назавжди (див. `CLAUDE.md`).

## Конвенції, яким має слідувати новий/змінений скрипт

Деталі — в [`CLAUDE.md`](./CLAUDE.md), коротко:

- **Ідемпотентність.** Повторний запуск без флагів не повинен нічого
  ламати — або нічого не робить (вже застосовано), або доробляє відсутнє.
- **Dry-run за замовчуванням**, `--apply`/`-Apply` — для реальної зміни
  системи. Виняток — ідемпотентні інсталятори софту (не мутують
  акаунти/файли): їм замість цього — `--check`/`-Check`.
- **Паролі/секрети тільки інтерактивним введенням.** Ніколи не аргументом
  командного рядка і не хардкодом у скрипті.
- **Одна невдача не повинна обвалювати весь скрипт.** Копіть помилки у
  список, друкуйте підсумок наприкінці, продовжуйте з рештою.
- **Пара файлів**: `NN_name.sh`/`.ps1` (код, англійською) + `NN_name.md` +
  `NN_name.en.md` (документація — українська/англійська, що робить, як
  запускати, обмеження).
- **Жодних приватних даних.** Ні абсолютних шляхів конкретних машин, ні
  реальних email/імен облікових записів, ні токенів/ключів — ні в коді,
  ні в коментарях, ні в прикладах команд.

## Тестування перед PR

Мінімум:
- `bash -n script.sh` (або `pwsh -Command "... Parser::ParseFile ..."`
  для `.ps1`) — синтаксис.
- `shellcheck script.sh` — для bash-скриптів, виправити принаймні
  warning+ рівня (info-рівня, наприклад відомий `SC2016` на літеральних
  `$HOME`-рядках у rc-файлах, — можна залишити, якщо він навмисний).
- Реальний прогін на чистій (або снапшотній/віртуальній) машині — якщо
  можливо. Якщо немає доступу до потрібної ОС для реального прогону — так
  і напишіть у PR, ревьюер може прогнати сам перед мержем.

## Після мержу

Мейнтейнер оновлює `CHANGELOG.md` (semver-бамп у `package.json`, якщо
виправдано) і відповідний рядок у `SCRIPTS_CHECKLIST.md` — окремо робити
це в PR не обов'язково, але вітається.

## Питання

Якщо щось незрозуміло з `CLAUDE.md`/`SCRIPTS_CHECKLIST.md` або конвенція
здається незручною — відкривайте issue з обговоренням, конвенції не
висічені в камені, якщо є аргумент їх змінити.
