### Новий скрипт 14 — прибрати рекламу/телеметрію Windows (2026-09-13)

Користувач попросив налаштувати новий акаунт так, щоб Windows «більше
нічого не питала» і система була максимально схожа на Linux — прибрати
рекламу/підказки, аналітику, зайві «зручності». Уточнив два питання перед
реалізацією: наскільки агресивно (вибрано: консервативно + телеметрія
машини, без Windows Update/Defender/видалення застосунків) і куди
додавати (вибрано: окремий новий скрипт №14, а не вбудовувати в 12).
Заразом зафіксовано важливий факт: локальний акаунт, створений через
`New-LocalUser` (як у `12`), НЕ проходить повний OOBE з питаннями про
приватність — ті питання бувають тільки при первинному налаштуванні самої
машини, вхід під новим локальним акаунтом уже нічого не блокує. Тому
скрипт вирішує іншу, реальну проблему — не «розблокувати вхід», а
прибрати ненав'язливі, але набридливі нагадування/рекламу/телеметрію.
`-Remove` перевірено лише статично (парсинг+рев'ю коду) — після
попереднього випадку в цій же сесії, коли живий тест деструктивного шляху
на реальній машині випадково зачепив реальне ПЗ, вирішено live-тести
деструктивних гілок для 12/13/14 більше не запускати самостійно;
фактичний прогін залишається за користувачем.

- [x] (2026-09-13) Додати `14_reduce_windows_bloat.ps1` — консервативне
      вимкнення реклами/підказок/телеметрії Windows, з `-Remove` для
      відкату.

### Прапорець -Remove (відкат) для 12/13 (2026-09-13)

Користувач попросив можливість відкатити дію скриптів — щоб повторні
прогони під час дебагу/тестування не залишали машину в невизначеному
стані. Додано `-Remove` до обох: `12_create_dev_user.ps1 -Remove [-Apply]`
видаляє ізольований акаунт (підтвердження щоразу, профільну папку не
чіпає); `13_setup_dev_environment.ps1 -Remove` робить `winget uninstall`
для встановлених пакетів (підтвердження щоразу, git identity/SSH-ключ не
чіпає). Живий тест деструктивного шляху на реальній машині під час
розробки був навмисно зупинений — `-Remove` перевірено лише статично
(парсинг + читання коду), фактичний прогін лишається на користувачі.

- [x] (2026-09-13) Додати `-Remove` до 12/13 для відкату дій; фактичний
      прогін на реальній машині — за користувачем.

### 12 падав на локалізованій Windows через жорсткі назви груп (2026-09-13)

Реальний прогін `12_create_dev_user.ps1 -Apply` користувачем (уже після
попереднього виправлення BOM/encoding) впав на
`Add-LocalGroupMember : Группа Users не найдена` — акаунт уже був
створений, `New-LocalUser` пройшов, впала саме перевірка групи. Причина:
скрипт шукав `Administrators`/`Users` за жорсткою англійською назвою, а
на RU/UA-локалі Windows ці вбудовані групи фізично називаються
«Администраторы»/«Пользователи». Виправлено пошуком за well-known SID
(`S-1-5-32-544`/`S-1-5-32-545`) — відтворено і перевірено на живій
кириличній машині (той самий баг, ті самі локалізовані назви груп), а не
навмання. Заразом виправлено суміжну прогалину: якщо акаунт уже існував
і передано `-Apply`, скрипт раніше вигодив без перевірки груп — тепер
доганяє членство і для вже існуючого акаунта, щоб перезапуск після саме
такого часткового збою реально його виправляв.

- [x] (2026-09-13) Виправити пошук вбудованих груп за жорсткою назвою —
      перейти на well-known SID; зробити перевірку груп ідемпотентною і
      для вже існуючого акаунта.

### 12/13 не запускались на чистій Windows-машині (2026-09-13)

Користувач повідомив, що не може прогнати `12_create_dev_user.ps1`/
`13_setup_dev_environment.ps1`. Розслідування (з реальним запуском, не
тільки читанням коду) знайшло три окремі причини: (1) справжній баг —
файли без UTF-8 BOM з em dash у рядкових літералах ламали парсинг
Windows PowerShell 5.1 на кириличному «language for non-Unicode
programs» (типово для укр. Windows) — виправлено додаванням BOM; (2)
відсутність прав адміністратора для `12` і (3) відсутній `winget` для
`13` — для обох додано покрокові інструкції виправлення прямо в
консольний вивід. Додатково — `13` тепер попереджає, якщо його запущено
від адміністратора (мало б запускатись від цільового користувача), і
акуратно пропускає git-identity/SSH-кроки, якщо `git`/`ssh-keygen` ще
не встановлені, замість `CommandNotFoundException`. Задокументовано:
розділи «Типові проблеми» в `scripts/12_create_dev_user.md`/
`13_setup_dev_environment.md` + «Швидкий старт на чистій
Windows-машині» в `README.md` (явно: це дві сесії, не одна команда).

- [x] (2026-09-13) Розібратись, чому 12/13 не запускаються на чистій
