# Чекліст запуску скриптів

**[English version](./SCRIPTS_CHECKLIST.en.md)**

Окремий від решти документації: тут — лише фізичний факт запуску
скриптів, щоб у будь-який момент було видно, який скрипт з якими
параметрами вже прогонявся і на якій стадії (сухий прогін / реальне
виконання).

**Конвенція параметрів (єдина для всіх скриптів проєкту, якщо не вказано
виняток):** без параметрів — сухий прогін (нічого не змінює);
`--apply`/`-Apply` — реальне застосування змін. Кожен скрипт при сухому
прогоні сам друкує готову команду з `--apply` для копіювання.

**Конвенція «перший запуск» (єдина для скриптів, які пишуть у
`scripts/logs/`):** перш ніж робити щось іще, кожен такий скрипт
перевіряє, чи є в `scripts/logs/` хоч один його власний лог. Якщо немає —
це його перший реальний запуск за весь час — друкує попередження і
запитує явне підтвердження (`[y/N]`), перш ніж продовжити. Відмова —
вихід без змін і без створення логу, тож наступного разу попередження
з'явиться знову. Підтвердження задається один раз за все життя скрипта.

**Винятки — №06 і №13 (`06_setup_new_dev_mac.sh`,
`13_setup_dev_environment.ps1`):** не мутують наявні файли/акаунти, а
ідемпотентно доставляють софт (самі детектять, що вже стоїть, і
пропускають), тому замість dry-run/`--apply` використовують
`--check`/`-Check` (тільки звіт про статус, нічого не змінює) і звичайний
запуск (ставить відсутнє). Також не пишуть свій лог у `scripts/logs/` —
конвенція «перший запуск» на них не поширюється.

**Ім'я файлу скрипта = номер його рядка нижче.** Якщо скрипт пізніше
допрацьовується (новий флаг/ключ) — файл **не перейменовується**:
правиться наявна база з тим самим ім'ям. Номер/ім'я закріплені за
скриптом один раз.

**Процес по кожному рядку:**
1. Скрипт доданий → рядок з'являється тут (обидва чекбокси порожні).
2. Скрипт реально запущений (сухий прогін або `--apply`/`-Apply`).
3. За логом/фактом — проставляється відповідний чекбокс.
