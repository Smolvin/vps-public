# 12_create_dev_user.ps1

**[English version](./12_create_dev_user.en.md)**

Windows-версія `09_create_profiles.sh`: створює **одного** ізольованого
(НЕ-admin) локального користувача `dev` — той самий принцип, що й на
Mac: рівно один admin-акаунт в архітектурі, все інше — standard user.

Див. `SCRIPTS_CHECKLIST.md` №12.

## Запуск

Від адміністратора:

```powershell
.\12_create_dev_user.ps1                  # dry-run
.\12_create_dev_user.ps1 -Apply           # реально створити
.\12_create_dev_user.ps1 -Apply -UserName sandbox   # інше ім'я
.\12_create_dev_user.ps1 -Remove           # dry-run: що видалить відкат
.\12_create_dev_user.ps1 -Remove -Apply   # реально видалити акаунт (відкат)
```

**Перший реальний запуск будь-коли** (немає жодного логу в
`scripts/logs/`) додатково друкує попередження і запитує підтвердження —
та сама конвенція, що й у `09_create_profiles.sh`. Спрацьовує один раз за
все життя скрипта.

| Параметр | Опис |
|---|---|
| `-UserName` | Ім'я нового (чи для видалення — наявного) користувача (за замовчуванням `dev`) |
| `-Apply` | Реально створити акаунт (за замовчуванням — тільки dry-run, друк). З `-Remove` — реально видалити. |
| `-Remove` | Відкат: видалити акаунт замість створення. Без `-Apply` — тільки dry-run (що саме буде видалено). |

## Як це працює

1. Перевіряє, що запущено від адміністратора.
2. Якщо це перший запуск за весь час — запитує підтвердження.
3. Якщо користувач з таким ім'ям вже існує — `[skip]`, не чіпає
   (ідемпотентно).
4. Інакше (тільки з `-Apply`): запитує пароль інтерактивно
   (`Read-Host -AsSecureString`, ніколи не в аргументах), створює
   `New-LocalUser`.
5. Перевіряє, що акаунт НЕ потрапив у групу `Administrators` — прибирає,
   якщо потрапив (ця роль має бути ізольованою).
6. Переконується, що акаунт складається у звичайній групі `Users`.

## Відкат (`-Remove`)

Якщо треба скасувати те, що зробив цей скрипт (наприклад, після тестового
прогону або помилки):

```powershell
.\12_create_dev_user.ps1 -Remove -UserName alex          # dry-run
.\12_create_dev_user.ps1 -Remove -Apply -UserName alex   # реально видалити
```

- Без акаунта з такою назвою — `[skip]`, нічого не робить.
- З `-Apply` — питає підтвердження **щоразу** (не тільки при першому
  запуску, як для створення — видалення акаунта незворотне на кожному
  прогоні, тож і підтверджувати варто щоразу), потім `Remove-LocalUser`.
- **Не видаляє** папку профілю (`C:\Users\<ім'я>`) і файли в ній — це
  окремий, ручний крок, якщо теж потрібно прибрати.

## Обмеження

- Ідемпотентний: наявний акаунт не чіпає, безпечно перезапускати.
- Не налаштовує робочий стіл/профіль для нового користувача.
- Не ставить dev-інструменти — для цього залогіньтеся під новим
  користувачем і прогоніть
  [`13_setup_dev_environment.ps1`](./13_setup_dev_environment.md).

## Це не «одна команда» — і це свідомо

Скрипт **не** заводить дев-оточення повністю сам. Створення ізольованого
акаунта (`12`, від адміністратора) і встановлення інструментів у ньому
(`13`, від самого цього акаунта) — це дві різні сесії Windows, тому що
акаунт, під яким запускається `13`, фізично повинен вже існувати і треба
бути залогіненим саме під ним (інакше git identity/SSH-ключ/winget
per-user пакети підуть у профіль адміністратора, а не `dev`). Повний
порядок дій на чистій машині — у [`README.md`](../README.md), розділ
«Швидкий старт на чистій Windows-машині».

## Типові проблеми

**`cannot be loaded because running scripts is disabled on this system`**
— виконання `.ps1`-скриптів заблоковано політикою PowerShell (типово на
щойно встановленій системі). Дозволити для поточного користувача (не
потребує адміністратора, діє тільки на скрипти, підписані чи локальні):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Або одноразово, без зміни політики взагалі:

```powershell
powershell -ExecutionPolicy Bypass -File .\12_create_dev_user.ps1
```

**`This script must run as Administrator`** — скрипт вивів це і зупинився
(з інструкцією прямо в консолі). Закрити вікно, відкрити PowerShell (або
Windows Terminal) через правий клік → «Запуск від імені адміністратора»,
перейти в цю ж папку (`cd`) і повторити ту саму команду.

**`Add-LocalGroupMember : Группа Users не найдена` (або `Администраторы`)**
— на локалізованій Windows (RU/UA) вбудовані групи фізично називаються не
`Administrators`/`Users`, а «Администраторы»/«Пользователи» тощо —
скрипт шукає їх за незалежним від локалі well-known SID, тож ця помилка
виправлена. Якщо впіймали її на старій версії скрипта: акаунт вже
створений (помилка стається після `New-LocalUser`), просто перезапустіть
`.\12_create_dev_user.ps1 -Apply` ще раз з оновленою версією скрипта —
він доженe членство в групах для вже існуючого акаунта, а не тільки для
нового.

**Створений акаунт не з'являється на екрані блокування одразу** — інколи
Windows оновлює список акаунтів на екрані входу тільки після перезавантаження
або `shutdown /l` (вихід з поточного акаунта). Якщо не з'явився — вийти з
поточного акаунта повністю (не просто заблокувати екран) або перезавантажити
машину.
