# 14_reduce_windows_bloat.ps1

**[English version](./14_reduce_windows_bloat.en.md)**

Прибирає нав'язливе з Windows: реклама/підказки в Пуску, авто-запуск
OneDrive при вході, Cortana/Bing-результати в пошуку Пуску, кнопка
Widgets на панелі задач, «підібрані під вас» поради з діагностичних
даних + рекламний ID, реклама Spotlight на екрані блокування — плюс
телеметрія на рівні всієї машини (політика `AllowTelemetry` + служба
DiagTrack).

Див. `SCRIPTS_CHECKLIST.md` №14.

**Свідомо консервативний скрипт.** НЕ чіпає навмисно (кожне з цього —
розмін функціональності чи безпеки на «тишу»): Windows Update, Microsoft
Defender, видалення вбудованих/попередньо встановлених застосунків, будь-
які служби, крім двох суто телеметричних нижче. Якщо потрібен «повний
дебloat» — це свідомо поза межами цього скрипта.

## Запуск

Від адміністратора (змінює політики HKLM і монтує чужі registry-хайви —
без адміністратора ніяк):

```powershell
.\14_reduce_windows_bloat.ps1                        # dry-run
.\14_reduce_windows_bloat.ps1 -Apply                  # реально застосувати
.\14_reduce_windows_bloat.ps1 -Apply -UserName sandbox # інший акаунт замість dev
.\14_reduce_windows_bloat.ps1 -Remove                  # dry-run: що відкат поверне
.\14_reduce_windows_bloat.ps1 -Remove -Apply           # реально відкатити
```

**Перший реальний запуск будь-коли** (немає жодного логу в
`scripts/logs/`) додатково друкує попередження і запитує підтвердження —
та сама конвенція, що й у `12_create_dev_user.ps1`. Спрацьовує один раз
за все життя скрипта для напрямку «застосувати»; `-Remove -Apply` питає
підтвердження **щоразу** (відкат незворотний на кожному прогоні, не
тільки при першому).

| Параметр | Опис |
|---|---|
| `-UserName` | Наявний користувач, чий вже створений профіль (якщо є) теж отримає налаштування, на додачу до Default-шаблону (за замовчуванням `dev`) |
| `-Apply` | Реально застосувати (за замовчуванням — тільки dry-run, друк). З `-Remove` — реально відкатити. |
| `-Remove` | Відкат: прибрати значення й повернути служби. Без `-Apply` — тільки dry-run. |

## Що саме змінюється

**На рівні профілю** (застосовується і до Default-профілю — щоб будь-
який майбутній новий локальний акаунт успадкував це одразу — і до
профілю `-UserName`, якщо той уже хоч раз логінився, тобто його
`NTUSER.DAT` уже існує):

- Реклама/підказки в Пуску та Параметрах (`ContentDeliveryManager`)
- Авто-запуск OneDrive при вході (тільки сам нагадувальний запис, не сам
  застосунок — OneDrive лишається встановленим, просто не лізе одразу)
- Cortana / Bing-результати в пошуку Пуску
- Кнопка Widgets на панелі задач — прихована
- «Підібрані під вас» поради з діагностичних даних + рекламний ID
- Реклама Windows Spotlight на екрані блокування

**На рівні всієї машини** (зачіпає всі акаунти, включно з тим
адміністративним, з якого запускаєте скрипт):

- Політика `AllowTelemetry` — мінімум, який дозволяє ця редакція Windows
- Рекламний ID — вимкнений політикою на рівні машини (поверх
  профільного значення вище)
- Служба «Connected User Experiences and Telemetry» (`DiagTrack`) —
  вимкнена
- Служба «WAP Push Message Routing Service» (`dmwappushsvc`) — вимкнена

## Як це працює

- Профільні значення застосовуються офлайн: скрипт монтує
  `NTUSER.DAT` кожного цільового профілю через `reg.exe load` в
  тимчасовий вузол `HKU\TempHive14_...`, читає/пише через нього, потім
  акуратно розмонтовує (`Remove-PSDrive` → `[gc]::Collect()` → `reg.exe
  unload`, щоб уникнути «hive still in use»).
- Кожен пункт ідемпотентний: якщо значення вже те, що треба — `[skip]`,
  нічого не чіпає. Одна невдача не зупиняє решту — підсумок `$Failed`
  наприкінці, як у `13_setup_dev_environment.ps1`.
- `-Remove` видаляє значення, які виставив цей скрипт (це повертає
  поведінку Windows за замовчуванням — значення просто не існували в
  чистій системі), і повертає обидві служби до їхнього типового
  стартового типу. **Не** намагається відновити запис автозапуску
  OneDrive (оригінальний командний рядок невідомий — після відкату
  увімкніть вручну через Диспетчер завдань → Автозавантаження, якщо
  треба).

## Обмеження

- Не відкочує те, що Windows уже змінила сама до першого запуску з
  `-Apply` — відкат знає тільки про те, що виставив сам цей скрипт.
- Не працює з профілем, який ще жодного разу не логінився і при цьому не
  є Default-шаблоном — у такому разі отримує налаштування тільки Default
  (і сам `-UserName`-акаунт успадкує їх при першому вході).
- Живий прогін (реальне застосування чи відкат) на справжній машині не
  перевірявся автоматично під час розробки — тільки статично (парсинг +
  рев'ю коду). Перший реальний запуск — за користувачем, з переглядом
  логу в `scripts/logs/14_reduce_windows_bloat_*.log`.
